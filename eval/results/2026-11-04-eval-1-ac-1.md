# Why the agent misses EVAL-1's shipping bug, 4 November 2026

The agent of D clean detected the bug `discount-includes-shipping` of EVAL-1 in 7 of its 15 trials across the history. The rate also moved between campaigns: 3/3 in smoke run 30, then 1/5 in smoke run 32 and 0/3 in its follow-up, run 33. This note reads the tests the agent wrote in the 11 trials of runs 30, 32 and 33 (`eval-trials` artifacts), with no model call.

## What the bug changes

- AC-1 asks for 10% off the subtotal, with shipping still computed on the subtotal before the discount.
- The bug takes the 10% off the subtotal plus shipping.
- Shipping is €4.90 below €50 of subtotal and free from €50 on. So the bug changes the result only when shipping is paid: 10% of €4.90 adds €0.49 to the discount. On a cart of €50 or more, a correct and a buggy implementation show the same figures.

## What the tests did

| Run | Trials | Bug detected | AC-1 tests per level | AC-1 carts |
|---|---|---|---|---|
| 30 | 3 | 3 | 2, 2 and 3 | each trial has one cart under €50, with €4.90 shipping |
| 32 | 5 | 1 | 1 in the 4 misses, 2 in the catch | misses: €53.50 or €55.00, free shipping; catch: €15.00 |
| 33 | 3 | 0 | 1 | €53.50, free shipping |

- **Every catch** has an AC-1 test whose cart is under €50, so shipping is paid. Examples: Notebook + Pen set, €10.50; two Pen sets, €12.00; Backpack alone, €49.00.
- **Every miss** has a single AC-1 test per level, on Backpack + Notebook (€53.50, 6 trials) or Backpack + Pen set (€55.00, 1 trial). Shipping is free, so the bug cannot show.
- **The misses are not wrong tests.**
  - They pass on the correct implementation, and they fail on the unimplemented one, as phase 1 requires.
  - They separate another plausible mistake: free shipping decided after the discount. €53.50 less 10% is €48.15, under the threshold, so that mistake would charge €4.90. The agent's own evidence says so: "An implementation that computes shipping after the discount would charge €4.90 and show €53.05."
  - What they miss is the second plausible mistake of the same sentence: the base of the discount.
- **The trials that caught it named both.** Run 30, trial 2: "One uses €53.50 (Backpack + Notebook), where a wrong implementation that computes shipping after the discount shows €4.90 instead of Free. The other uses €12.00 with paid shipping."

## Why

- **The prompt allows stopping at one case.** Rule 5 of `.claude/agents/qa-writer.md` names the right case: "apply the rule while another rule also applies (a fee is charged, a limit is reached)". But it asks for "at least one case where a plausible wrong implementation shows a different result". A test that separates one plausible mistake satisfies it. In 7 trials out of 11 the agent named one mistake for AC-1 and wrote one case.
- **The same agent did both.** The prompts, hooks, settings and Claude Code version are those of D clean in every one of these campaigns (agent `43cb10d883b4`), with the same served models. Between runs 30 and 32, the only change to `eval/trial.ts` is a warning printed by the report job, not by the agent's runner. Whether the agent writes one AC-1 case or two varies from trial to trial.
- **No time effect that can be tested.** The three campaigns up to smoke run 30 detect the bug in 6 of 7 trials, the two since in 1 of 8. That split was chosen after seeing the data, so it is not a test.
- **The scoring is right.** Each missed test passes on the bug's variant, so the bug is not detected. The hidden tests of the corpus check both carts, with paid and with free shipping.

## What could fix it

Tried since, in [2026-11-04-rule-5.md](2026-11-04-rule-5.md): the rewording below found the bug 3 times out of 3, but raised false positives as much, and was reverted.


- **A wording of rule 5** that asks for one case per plausible wrong implementation, not one case per criterion. For instance: name each rule applied to the wrong base, at the wrong time, or not at all, and give each one a case. It must stay generic, with no word about discounts or shipping: the corpus must not leak into the prompt.
- **Validating it** would need a full run, compared ticket by ticket with D clean.
  - EVAL-1 alone would not do: a prompt tuned on the ticket that revealed the problem says nothing about the others.
  - More cases per criterion also cost turns and time, which the comparison measures.
- **A new ticket** with two rules interacting in the same way would test the fix on a ticket it was not tuned on (corpus extension, P3).

## Limits
