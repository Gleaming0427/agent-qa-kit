# The kit on a large project: immich, 7 November 2026

The kit had only run on its demo shop. This trial installs it into a copy of [immich](https://github.com/immich-app/immich), a self-hosted photo application, at commit 87ef895 of 7 November. immich is a pnpm 12.16.1 workspace of 12 projects; its web application uses SvelteKit, Vitest and Playwright. No model was called: this measures the installer, the install step of the workflows and the full suite, not the agents.

## What happened

1. **`init`** refused to choose between the two packages that have Vitest and Playwright, `e2e` (it needs the whole server, with Docker) and `web`. With `--app web`, it installed the kit and found pnpm 12.16.1 in `packageManager` at the workspace's root.
2. **`doctor`** reported two things to change in the project: its browser tests live in `test/medium/specs`, not in `e2e/` where the agents write theirs, and no test was tagged `@smoke`.
3. **immich's own CI** showed two things the kit could not handle, fixed in the kit before going on:
   - the web application imports `@immich/sdk`, a package of the workspace whose built entry is not committed. The install step now runs the application's `qa:setup` script, and `doctor` asks for it, with the build immich's CI runs;
   - immich pins Node.js 26.13.0 in `.nvmrc`, and the workflows forced 22. They now use the application's `.nvmrc` or `.node-version`.
4. **Adapted the copy**, four files: Playwright's `testMatch` also takes `e2e/`, a timeline journey is tagged `@smoke`, `qa:setup` builds the SDK, and `test:e2e` builds the application first, since the browser tests run against `vite preview`. `doctor` then reported one more false problem, fixed in the kit: it looked for `@smoke` in `e2e/` only, while Playwright, with `testDir: '.'` and that `testMatch`, runs `test/medium/specs` too.
5. **The install step** (`qa/ci-install-app.sh`, the script of the workflows):
   - pnpm 12.16.1 installed from the frozen lockfile, 2,754 packages in 22 s;
   - `qa:setup` built the SDK, and Playwright's system dependencies were installed;
   - no file of the repository changed.

   Only the browser download failed: this container's network does not allow Playwright's download host. GitHub's runners do.
6. **`doctor --run`**, the full suite as QA verify runs it, in 3 min 46 s:
   - unit tests: 518 of 518 pass;
   - browser tests: 113 of 115 pass, the `@smoke` journey included;
   - both reports are written and read.

## The two failures

Both are in `detail-panel.spec.ts`: the detail panel does not close on `i`, and the description field is not found after moving to the next photo. They fail in 3 reruns out of 3.

Their cause is not known:
- this container has Chromium 153, where Playwright 1.64.1 expects 156, and Node.js 22, where immich uses 26;
- the spec was added on 2 November and changed on 5 and 6 November;
- this session cannot see immich's CI results for the commit.

They are not counted as a fault of immich or of the kit. Running the same copy on GitHub Actions, with the right browser and Node.js, would settle it.

## What this does not show

- **No agent ran.** Whether the writer can write good tests in immich's setup, with its fixtures and page objects (`#test/medium/fixtures.ts`), is not measured.
- **Not run on GitHub Actions**, with the workflows themselves.
- **A difference to decide on later.** immich's Playwright retries a failed test twice in CI, while the kit's full suite counts a test that passes on a retry ("flaky") as a failure. On a project with flaky tests, QA verify would be stricter than the project's own CI.
